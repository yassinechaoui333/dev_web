# Shared data contract v1

IDs are UUID strings except source business identifiers, which remain strings including leading zeros. JSON uses camelCase; PostgreSQL names follow Prisma model/field names. createdAt/updatedAt are UTC RFC3339 timestamps. Prisma is authoritative for nullability, foreign keys and indexes.

| Table | Main columns and types |
|---|---|
| User | id UUID PK; email varchar(254) unique normalized lowercase; name varchar(100); passwordHash text; role USER/ADMIN; active bool; createdAt/updatedAt timestamptz(3) |
| Session | id UUID; tokenHash text unique; userId FK; expiresAt/createdAt timestamptz(3) |
| Dataset | id UUID; ownerId FK; title varchar(200); description text; category varchar(100); source varchar(500); currency char(3); dateFormat text; timezone text; createdAt |
| ImportJob | id UUID; datasetId FK; filename varchar(255); contentHash char(64); retryCount integer; status pending/processing/completed/failed; totalRows/processedRows/acceptedRows/rejectedRows integer; error nullable text; createdAt/completedAt nullable timestamp |
| RawRecord | id UUID; datasetId/importJobId FK; sourceRow integer; values JSONB; validationErrors nullable JSONB |
| SalesRecord | id UUID; datasetId/importJobId/rawRecordId FK; invoiceNumber/productCode/description/country text; quantity/unitPrice decimal(18,4); invoiceDate timestamptz(3); customerId nullable text; isCancellation bool |
| Dashboard | id UUID; ownerId/datasetId FK; title varchar(200); config JSONB; createdAt/updatedAt |
| DashboardShare | id UUID; dashboardId/userId FK; createdAt; unique dashboardId+userId; read-only only |
| Activity | id UUID; actorId nullable FK; action varchar(100); entityType varchar(50); entityId nullable text; metadata nullable JSONB; createdAt |

Dataset deletion cascades its import/raw/clean/dashboard/share records. Users with owned datasets/dashboards cannot be deleted; administration deactivates accounts instead. Session/share user references cascade; activity actor is set null if deletion is introduced later.
Composite FKs prevent raw and clean records from pointing at a different dataset/import. Each raw row yields at most one clean record. Source rows start at 2 for the first data record with a header; quoted multiline CSV records count as logical records. Raw values retain original strings, empty fields and original column names.

## Import and sales semantics
Dataset currency is a single uppercase ISO 4217 code supplied at creation and immutable after import. v1 supports currencies with two minor-unit digits (GBP, EUR, USD, MAD); reject other codes. No currency conversion or cross-currency totals.
Dataset dateFormat is ISO8601 or an explicitly selected DMY_HM format (dd/MM/yyyy HH:mm). Never guess ambiguous dates. timezone is an IANA timezone, default UTC, immutable after import. ISO timestamps with offsets respect the offset; timestamps without offsets use the dataset timezone. Reject invalid/nonexistent/ambiguous local times and invalid calendar dates. Persist UTC timestamps; return UTC RFC3339.
Quantity and unitPrice parse decimal strings, never floating-point money. Preserve up to four fraction digits; reject excess precision, overflow and negative unit prices. Zero quantity or price is allowed and flagged for quality review. customerId is null for blank/whitespace values. Trim identifiers and country but preserve case and leading zeros; do not infer numeric customer IDs.
Cancellation is an invoiceNumber starting with C, case-insensitive. Returns are negative quantities. Normalize cancellation quantities to -abs(quantity), keeping positive unitPrice; a cancellation already negative remains negative. Retain original values in RawRecord.
Each row netAmount = quantity * unitPrice (decimal arithmetic). Net revenue includes signed returns/cancellations; gross sales sum positive net amounts; returns amount is abs(sum negative net amounts). Compute sums before rounding half-up to two decimals for presentation. API money/quantity fields are decimal strings, never JSON numbers. Do not persist rounded line totals.
Import counters exclude headers: processedRows = acceptedRows + rejectedRows <= totalRows; completed implies equality. Reject duplicate sourceRow within a job; repeated invoice numbers are valid line items. SHA-256 of the original file bytes identifies an upload within a dataset; unique(datasetId, contentHash) blocks repeated files, including concurrent requests. A failed import retries the same job ID, increments retryCount, and removes that job's staging rows atomically before retry. Different files may contain legitimate identical lines; never deduplicate individual transactions by their values. Analytics includes completed jobs only so partially imported data is invisible.

## Shared filters and pagination
Lists accept page (1-based default 1), pageSize (default 20, maximum 100). Response: {data: [...], meta: {page, pageSize, total, totalPages}}; empty totals yield totalPages=0. Stable ordering createdAt desc then id desc unless explicitly documented.
Sales filters: from inclusive, to exclusive UTC RFC3339 timestamps with explicit Z or offset; country exact trimmed country string; productCode exact case-sensitive string. One value each, combined AND. Reject unknown/repeated filter keys, invalid intervals, and missing timestamp offsets with 400. Frontend converts inclusive date selections to [start, next-day-start) using the dataset timezone before sending. Country uses canonical trimmed source labels (e.g. United Kingdom), not inferred ISO country codes. No fuzzy matching. Default is all dates/countries/products and signed returns included.
Activity list uses page/pageSize only in v1.

## Access
Dataset CRUD, imports, raw rows, exploration and /api/datasets/{datasetId}/analytics/* require dataset ownership. Admin has no implicit content access.
Dashboard create requires ownership of dataset; dashboard owner must equal dataset owner. Dashboard edits/deletion/sharing require dashboard ownership. Shares reference existing active registered users, never emails/public URLs as bearer credentials.
A recipient can GET a shared dashboard and GET /api/dashboards/{dashboardId}/data using a read check. The data endpoint evaluates only the saved chart config and saved filters against the linked dataset. It cannot accept arbitrary filters, SQL, raw-record requests or dataset IDs. Shared recipients cannot call dataset/analytics endpoints, alter config, reshare or export raw rows. Revoking a share takes effect on the next request.
Reusable access helpers return 404 for missing/inaccessible resources; validate UUIDs before calling them. Ordinary users receive 403 for admin endpoints. Inactive users lose access to all authenticated routes. Activity metadata must never contain password hashes, cookies, raw tokens, or sensitive raw dataset values.

## Finalized team handoff additions
These additions replace the uncommitted draft conventions, before foundation-v1 is published. Dataset and Dashboard use **title**; only User uses name. Dataset description/category/source default to empty strings. ImportJob.contentHash is required lowercase SHA-256; retryCount starts at 0. Dashboard.config contains version=1, filters, charts and layout. A composite FK ensures dashboard owner equals linked dataset owner.

Ahmed retains the original CSV securely for pending/failed jobs. Source bytes and temporary worker files stay outside public static directories. The accepted file is CSV UTF-8 with optional BOM, comma delimiter, double-quoted fields and required case-sensitive headers: InvoiceNo, StockCode, Description, Quantity, InvoiceDate, UnitPrice, CustomerID, Country. CustomerID header is required but values can be blank. Reject duplicate/missing headers; allow additional columns only in raw values. Limit files to 10 MiB, 100,000 logical records and 64 KiB per field. Reject malformed quoting and invalid UTF-8 as failed jobs. Persist pending before returning 202. Complete the job in a transaction only after all raw/clean rows and counters are consistent. Every normal dataset/analytics read must restrict importJob.status=completed; failed/processing jobs remain invisible. Failed-job retry retains the original source and uses the same job ID; deletion must also clean retained upload files. The importer implementation and worker startup belong to Ahmed.

### Business metrics for Taha and Abdelali
Net revenue includes signed returns. orderCount is distinct invoiceNumber among filtered rows with quantity>0 and isCancellation=false; multiple positive lines from the same invoice count once. Return-only invoices do not count as new orders. averageOrderValue = netRevenue/orderCount, rounded half-up to two currency decimals, null when orderCount=0. Empty summaries return recordCount=0, orderCount=0, netRevenue/grossSales/returnsAmount='0.00', averageOrderValue=null. Empty aggregate series return []. No conversion across currencies.

The explorer belongs to Taha at /api/datasets/{datasetId}/analytics/records; metadata at /analytics/info. Ahmed owns /raw-records and /imports/{importJobId}/rejections. Explorer search is a literal case-insensitive substring across invoiceNumber, productCode, description, customerId and country; maximum 200 characters. Sorting allows invoiceDate, invoiceNumber, productCode, quantity, unitPrice and country only, with id as a stable tiebreaker in the same direction. Default invoiceDate desc/id desc. All filtering and paging is server-side.

Analytics /summary, /top-products, /sales-by-country and /revenue-over-time use the same completed-job sales filters. Top products sort netRevenue desc/productCode asc (limit 1..100, default 10); deterministic description is lexicographically smallest accepted description per product code. Country groups use the documented orderCount semantics. Time buckets align to dataset timezone, week begins Monday; return UTC periodStart; omit empty buckets. interval=day|week|month, default day. Parameterize queries and whitelist SQL column names; never interpolate arbitrary sort fields.

Comparison accepts compareDatasetId or compareFrom+compareTo. Both periods use [from,to) boundaries and the same country/product filters. Cross-dataset comparisons default to the current date filter when no comparison dates are supplied. Check ownership of both datasets and reject different currencies with 400 INCOMPATIBLE_CURRENCY. Absolute change=current-previous; percentage=100*change/abs(previous), null for zero or null baseline. AOV deltas are null when either AOV is null. Labels identify dataset title and period for both sides.

Shared dashboard data accepts no query filters or raw export requests. Owner edits saved filters/config before sharing; every widget uses that single saved filter set. Values are decimal strings; KPI AOV may be null. Taha provides internal aggregation functions accepting an already-authorized dataset scope; Abdelali's data route obtains scope through requireDashboardAccess, reuses those functions, and returns only configured widget results. Never call an ownership-only HTTP endpoint as a shared recipient or make analytics public.
